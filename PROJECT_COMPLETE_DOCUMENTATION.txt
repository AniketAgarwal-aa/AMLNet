1. EXECUTIVE SUMMARY
--------------------
AMLNet is a synthetic-data AML research and investigation prototype. It models
accounts as graph nodes and transfers as directed edges, computes account-level
features, produces GNN and rule-based risk signals, detects transaction patterns,
and exposes the results through a FastAPI API and React/Vite interface.

Primary domain: financial crime analytics / AML.
Supporting domains: graph analytics, graph machine learning, data engineering,
full-stack software engineering, database engineering, cloud deployment, security,
and reproducible research.

Maturity: functional research/demo prototype, not a bank-production AML system.
The application uses synthetic AMLNet data. IBM AMLSim is an optional local
research input and is never automatically imported into production.

2. SCOPE, USERS AND OBJECTIVES
------------------------------
Users are analysts, developers, students, and researchers investigating synthetic
account activity. The system is intended for learning, demonstration, and model
comparison. It is not a criminal-conduct determination, regulatory decision,
customer-risk adjudication, or production compliance certification.

Objectives implemented:
- Explore account and transaction relationships.
- Compute explainable graph/account features.
- Classify suspicious accounts with a small GCN and Logistic Regression baseline.
- Combine GNN probabilities with rule evidence into a 0–100 investigation score.
- Detect cycles, rapid transfers, fan-in, and fan-out patterns.
- Persist data and model artifacts using SQLAlchemy.
- Provide dashboard, investigation, graph, alert, performance, and management views.
- Preserve a reproducible IBM AMLSim research pipeline outside production.

4. ARCHITECTURE
---------------
```text
React/Vite + Recharts + Cytoscape
             │ JSON REST / VITE_API_BASE_URL
FastAPI + SQLAlchemy + validation + CORS
             │
SQLite (local) / Neon PostgreSQL (production)
             │
NetworkX directed graph → account features → StandardScaler
             │                         └→ rule pattern engine
             └→ PyTorch Geometric GCN → probabilities
                              └→ weighted final risk → alerts/API/UI
```

The original directed graph is retained for financial-pattern detection. The
standard GCN receives a symmetrized edge_index for message passing; this does not
erase sender/receiver direction from transactions or the rule engine.

Deployment architecture is GitHub source, Render FastAPI/Docker, Vercel React,
and Neon PostgreSQL. Production credentials are private environment variables.

10. AML DOMAIN AND ALERT LOGIC
------------------------------
Cycles may indicate circular movement of funds; rapid transfers may indicate short
holding periods; fan-in indicates concentration from multiple counterparties; and
fan-out indicates distribution to multiple counterparties. These are investigation
signals, not proof of money laundering. Human review and additional context are
required in any real deployment.
